# Wave 1の新しい運用

固定脚本2本の研究版だけを使用する。対話型の参照作品は、この研究の対象に含めない。

## 版と割当て

研究の正本は [study.json](../research/studies/wave1/study.json)。公開ビルドで対象の公開IDを固定し、研究の実行・表示の実装ハッシュを加えた定義全体からstudy revisionを計算する。読み込んだ研究定義と実行中の画面の版が違う場合は開始しない。凍結する際は次を実行し、[凍結情報](../ops/wave1-release.json)を更新する。

```bash
npm run build
npm run freeze:study
npm run verify
npm run test:browser
```

参加者URLは `?study=wave1&participant=P001&cohort=AB`。20件の割当ては [CSV](../ops/wave1-participant-links.csv) に保存し、10 AB / 10 BAとする。

```bash
npm run links -- --count 20 --seed 20260904 --output ops/wave1-participant-links.csv
```

旧 `pid`、`order`、`reset` パラメーターや旧回答JSONは引き継がない。同じ参加者IDに異なる割当てや研究版を混在させる操作はエラーにする。リセットを誘発するURLは提供しない。試走は `QA_*` など専用ID、新しい研究では新しいstudy IDを使う。

## 実施手順

1. 固定した成果物とA/Bの異なる立ち絵で、担当者が通しの読解・操作・所要時間を確認する。
2. 配信したURLを清潔なブラウザー状態で確認する。ローカル成功だけで公開済みとは扱わない。
3. 対象者へ割当てURLを渡し、「短いミステリーを2本、表示順に遊んでください」と伝える。
4. 2本終了後、最初の感想を回答・保存してもらう。
5. 保存後の停止画面で自由な感想を聞く。役を変えて再登場する仕組みはまだ説明しない。
6. 「次の質問へ」で企画を明かし、後半の回答を保存する。
7. 参加者JSONを書き出し、IDと割当てを照合して回収する。

状態は `blind → pause → revealed → done`。最初の回答は保存後に上書きできない。ブラウザー再開後も停止位置を維持する。完了判定はセッション状態から行い、分析ログの有無に依存しない。

自由質問例は「3人について気づいたことはありますか」「信じたい、疑いたくないと感じた場面はありますか」「ミステリーとして納得できなかったところはありますか」。誘導する前に自発的な言葉を記録する。

## 分析

```bash
npm run analyze -- test-results/ --output build/wave1-analysis.json
```

入力は `research-export/1` のみ。別study revision、重複参加者、重複イベント、不正回答、時刻の不整合を拒否する。途中で終わった参加者も読み込める。人数、完了数、AB/BA、人物ごとの評価、役変更への期待、感情と推理、次に見たい人物、自由回答、誤答回数、所要時間を集計する。欠測の平均はnullになり、ゼロ点へ置換しない。

所要時間はセッション開始から完了までの経過時間で、中断や離席も含む。人が計測した実プレイ時間と併記する。分析ツールはアンケートの数値を正規化してから集計し、完了済み参加者と未完了者を区別して返す。

## 解釈の基準

研究仮説は、H1「役が変わっても人物として認識され、次の役を見たい」、H2「人物への感情が推理体験を強くする」。少人数の方向性調査として、数値だけで成否を決めない。

- 人物同一性・役変更への期待は4前後以上を強い手掛かり、3台を混在、3未満を弱い手掛かりとして読む。自発的な発言と突き合わせる。
- 感情が推理へ影響したという回答が半数程度以上でも、具体的な場面の説明と、その後の納得があるか確認する。
- AB/BAの差が1点程度あれば、順序による誘導を検討する。
- 事件自体が不公平・自明と繰り返し評された場合、人物の高評価だけで形式を肯定しない。
- 1本8〜15分を目安として、8分未満の薄さ、18分超の疲労を人の通しプレイで確認する。自動テスト時間は評価に使わない。

この移行で機械検証したのは操作とデータの成立。実参加者による面白さ、人物同一性、時間配分の評価は未実施として保持する。調査中の変更は新revisionとして明確に分け、結果を混ぜない。
