# 08 — Open Questions

This file is intentionally a backlog of unresolved product/design questions.

## Product / audience

- What is the exact target demographic and primary use occasion?
- Is “30 minutes” the median, the maximum, or one of several formats?
- How often should new mysteries be released?
- Is the first release a catalog, a recurring feed, seasons, or another structure?

## Monetization

- What exactly is paid: subscription, mystery packs, Prince-related goods/content, passes, cosmetics, bundles, ads, or combinations?
- How do we monetize characters without making character attachment an obligation?
- Do roles/casting combinations themselves become paid content?
- How much of the mystery catalog must be free for acquisition?

## MYSTERY WORLD

- Does it exist primarily as UI/brand framing or as a navigable virtual space?
- How much fiction, if any, should it have?

## CROWN MASTER ZERO

- Is the name final?
- How stylized/fictional should the persona be?
- Is ZERO a real-person avatar, an illustrated avatar, or both?
- How often should ZERO appear so the persona retains informational/status value rather than becoming noise?

## PRINCE CORE

- What is the minimum schema required to preserve recognizable character identity across radically different roles?
- Is the name itself always fixed?
- How much visual variation is allowed by role?
- What role variations cause identity dilution?

## Mystery formats

- Murder as default vs broader incidents?
- How much freedom does a work have to alter the standard 30-minute structure?
- How many cast members best balance character appeal and deduction complexity?

## Game interaction

- What capabilities belong in MVP?
- How much should be reading vs active inference?
- Should wrong deductions have consequences?
- Should mysteries support multiple paths to the same solution?
- What reusable interaction is uniquely memorable enough to become a signature of MYSTERY PRINCE?

## AI production

- Which model(s) and orchestration approach?
- What is the MASTER STORY schema?
- What checks can be deterministic vs model-based?
- What makes a mystery “publishable” in automated scoring?
- How many generated candidates should be explored per release?
- How should human editorial feedback improve later generation?

## Technical

- Client stack?
- Content packaging/versioning format?
- Offline vs streamed assets?
- Schema migration strategy as the Mystery OS evolves?
- Backward compatibility for old mysteries when new renderer versions appear?
