# 00 — Vision and Principles

## Vision

Create a long-running entertainment IP where users repeatedly encounter attractive male characters through genuinely entertaining mysteries, while an AI-assisted production system makes it possible to produce a broad and growing catalog without reducing every work to low-quality generated filler.

## The product has two layers

### 1. MYSTERY PRINCE — consumer-facing IP
A character-first mystery entertainment brand for a primarily female audience.

### 2. Mystery creation system — production capability
A system that helps creators produce playable mystery games efficiently by combining whole-work design, structured mystery logic, reusable assets and a reusable runtime.

These layers should support each other, but must not be confused. Users do not need to think of the app as an “AI tool.”

## Core principles

### DECIDED — Character-first business, real mystery game
Characters are the durable IP asset, but the mystery cannot be a disposable excuse for character marketing. A user should be able to say both:

- “I like this Prince.”
- “That mystery was actually good.”

### DECIDED — Whole work before decomposition
Quality starts by designing the whole 30-minute work: hook, cast, central question, truth, reversals, climax, emotional aftertaste.

Only after the complete work is compelling should it be decomposed into mystery logic, game interactions and presentation.

### DECIDED — AI assists production before runtime
For the initial product, AI is used during authoring and production. Published mysteries are packaged content. Runtime LLM/API generation is not required for ordinary play.

Rationale:
- predictable API cost
- predictable latency
- stronger QA
- stable content ratings/safety
- easier voice/visual production
- easier debugging
- easier deterministic replay

### DECIDED — Content semantics must outlive today’s UI
A mystery should not encode “tap this button at (x,y).” It should encode the meaning of the situation and valid interactions.

Presentation can then evolve from simple 2D UI to richer interaction later.

### DECIDED — Reuse high-quality assets, not low-quality everything-generation
The production system should combine:
- professional character assets
- background/scene libraries
- props/evidence assets
- UI components
- music/SFX/effects
- structured game capabilities
- AI-assisted story/game data

AI does not need to generate every pixel at runtime.

### DECIDED — Character identity is not the same as character biography
A Prince may recur while the fictional role changes from work to work. The IP owns the recognizable “person,” not one irreversible life timeline.
