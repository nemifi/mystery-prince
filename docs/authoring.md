# 制作から公開まで

`works/the-2330-message/` が固定脚本の完全な制作例になる。

| ファイル | 正本として持つ情報 |
| --- | --- |
| `intent.json` | 問い、狙い、機械的な成立条件、人が評価する条件 |
| `roles.json` | 作品内の役のIDと肩書き |
| `casting.json` | 役→キャラクター→立ち絵の割当て |
| `rules.json` | 真相、証拠IDと種類、仮説の前提、命令、到達関係 |
| `performances/ja.json` | 台詞、見出し、選択肢表示、反応、証拠の説明文 |
| `assets.json` | 論理資産ID→ソースファイルと説明 |
| `realizations.json` | 公開する版、体験形式、演出、研究用編集 |

役のIDはキャラクター名から独立させる。表示文には `{{role:security-director.name}}` を使う。`.label` は役の肩書きになる。未知の役や未解決の参照はコンパイルエラーになる。

コンパイラーは証拠より前の推理要求、存在しない役、到達できない終幕、選択肢と表示の不一致、配役・資産の参照切れを拒否する。台詞の魅力、解釈の説得力、推理の面白さは機械判定で完了扱いにしない。

## 研究版

`research/studies/wave1/*-overlay.json` はcue ID、対象フィールド、変更前全文、変更後全文を明示する。元の台詞と一致しなくなるとビルドを止める。編集は配役の文字列束縛前に適用する。

描画後の単語置換、fetchやDOMの監視は行わない。通常版と研究版は同じルールを持つ別公開版になる。

## 対話型

`works/the-unwritten-alibi/` は作品意図、design、資産、公開版選択を持つ。designは役、質問トピック、語彙、鍵の印、導入を定義し、完成済みの真相や脚本ノードは持たない。

初期化で生成器が真相と証拠の関係を作る。自由入力は明示された3トピックをローカルに解釈する範囲で動作する。汎用会話AIを装うUIにはしない。

## 公開ビルド

```bash
npm run build
npm run verify
```

形式別コンパイラー、商品側の制作条件、資産の形式チェックを通し、参照資産だけをハッシュ名で複製する。対応画像形式はJPEG/PNG/WebP/SVG。ソースパスはリポジトリー内に制限する。SVGは外部参照と実行要素を禁止する。形式ヘッダーの検査と実ブラウザーでの復号・表示は別々に行う。

`dist/site/publications/` に公開版、`dist/site/assets/` に資産、`dist/reports/` に入力ソースとノード対応、機械検証と人の評価状態を出力する。生成物を直接編集しない。

A/B立ち絵は各役専用の別資産を維持した。壊れていた列車背景は新しいSVGへ置き換え、対話型の2つの立ち絵参照は復号可能な既存素材へ変更した。[資産の由来](../assets/artwork/PROVENANCE.md)を参照する。

## 新形式の追加

1. 領域の内容・状態・命令・観測を定義する。
2. 入力の読み方とコンパイラーを `experience-profiles/` に実装する。
3. エンジンとプレゼンターを実装する。
4. [形式登録](../experience-profiles/registry.mjs)と[実装登録](../implementations/modules.mjs)に追加する。
5. 商品の組立てで実装を選択し、作品の公開版選択に指定する。
6. 正常系、不成立系、復元、別実装との交換を検証し、公開する。

既存の基盤や他形式の状態を変更せずに追加できることをレビューする。
