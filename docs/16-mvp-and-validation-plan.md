# MVP Boundary and Validation Plan

Status: WORKING

## What the first phase must prove

The first product phase is not intended to prove every future platform feature. It should test the format’s fundamental user value before investing in broad platform infrastructure.

### H1 — Star-system hypothesis
A recurring PRINCE can appear in independent works with different ROLEs and fictional biographies while remaining recognizable and becoming more attractive as a durable character identity.

### H2 — Character x Mystery hypothesis
Character emotion and mystery reasoning strengthen each other rather than feeling like an attractive-character ADV with an unrelated puzzle layer.

### H3 — Platform-brand hypothesis
Independent works can still be perceived as releases from one MYSTERY PRINCE platform without requiring a shared fictional continuity.

### H4 — AI-production hypothesis
Authoring-time AI can eventually reduce cost/time while maintaining release-level quality. This is important but secondary to H1/H2 in the earliest validation.

## Concept Prototype

Before a full app, test H1/H2 with approximately:

- 3 recurring PRINCES
- 2 independent EXPERIENCES
- strongly different worlds and ROLE assignments
- short but polished vertical slices, roughly 10–15 minutes each

The same PRINCES should be intentionally recast so that continuity of character identity is stressed rather than trivially preserved.

Observe whether users naturally express reactions such as “this still feels like him,” “I like this version of him,” “I want to see what role he plays next,” and whether affection creates meaningful tension with suspicion and deduction.

## MVP proper

If the format hypothesis survives concept validation, build:

- one Runtime v1
- one Realization format
- the minimum PRINCE/EXPERIENCE/CASTING model
- an authoring workflow using AI offline
- multiple release-quality independent mystery experiences

Target play length may be approximately 30 minutes, but play length is a current product choice, not platform identity.

## Initial non-goals

Do not initially implement runtime generative AI, free-form AI conversation, 3D exploration, AR/VR, multiplayer, persistent character-story relationships, long-term character memory, elaborate collection systems, multiple runtimes, creator SDKs, universal capability plugins, or fully automated release decisions.

Future extensibility should be preserved through boundaries and stable identity—not by implementing future features early.

## Architectural success condition

Adding another ordinary EXPERIENCE for Runtime v1 should primarily be a content/authoring operation, not custom application engineering.
